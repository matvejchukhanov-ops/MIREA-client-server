# Протокол обмена

Версия: **2.0** — файловый менеджер.

Документ описывает договорённость между клиентом и сервером: транспорт, формат
сообщений, команды и коды ошибок.

---

## 1. Транспортный уровень

| Параметр | Значение |
|---|---|
| Протокол | TCP |
| Семейство адресов | IPv4 (`AF_INET`) |
| Тип сокета | `SOCK_STREAM` |
| Адрес по умолчанию | `127.0.0.1` |
| Порт по умолчанию | `9000` |
| Кодировка | UTF-8 |
| Инициатор соединения | Клиент |
| Модель обмена | Запрос — ответ, строго по очереди |

Соединение живёт, пока клиент не отправит `quit` или не закроет сокет. Вход
(`login`) действует в пределах соединения: новое соединение начинается без входа.

Сервер **никогда не отправляет ничего по своей инициативе**, кроме отказа
`SERVER_BUSY` сразу после подключения при исчерпании предела клиентов. На каждый
запрос приходит ровно один ответ.

Шифрования нет: пароль и файлы передаются открытым текстом. Работа рассчитана
на `localhost` или доверенную сеть (см. [security.md](security.md#13-что-не-защищено)).

---

## 2. Границы сообщений (фрейминг)

**TCP не сохраняет границы сообщений.** Он гарантирует только, что байты дойдут
все, в правильном порядке и без искажений. Два вызова `send()` могут прийти
одним `recv()` или разрезаться на произвольные куски. Поэтому границы задаются
явно.

**Одно сообщение — одна строка, завершённая переводом строки (0x0A).**

- Возврат каретки (0x0D) перед переводом строки игнорируется — чтобы сервер
  можно было проверять telnet-клиентом с Windows.
- Внутри сообщения перевода строки нет: JSON сериализуется в одну строку, а
  переводы строк внутри значений (например, в содержимом файла) экранируются
  самим JSON как `\n`.
- Приём — с накоплением в буфер: дописывать прочитанное, выделять завершённые
  строки, остаток хранить до следующего чтения.

### Ограничение размера

Предел кадра — **2 МБ** (`FM_MAX_FRAME_SIZE`). Кадр несёт содержимое файла,
поэтому он заметно больше предела файла (256 КБ): в худшем случае JSON
записывает байт шестью символами (`\u0001`). Сервер не запустится с настройками,
при которых файл предельного размера не помещается в кадр.

При превышении сервер отвечает `FRAME_TOO_LONG` и **закрывает соединение**:
позиция в потоке потеряна, и неизвестно, где начинается следующее сообщение.

Чтение, вернувшее ноль байт, — единственный корректный признак того, что
противоположная сторона закрыла соединение.

## 3. Формат сообщений

Тело кадра — **JSON-объект**.

### Запрос

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `cmd` | строка | да | Имя команды, до 64 символов |
| `id` | строка или число | нет | Возвращается в ответе без изменений |
| остальные | — | зависит от команды | Аргументы команды |

Строковые аргументы, кроме содержимого файла, ограничены 4096 символами.
Логические флаги принимаются только как `true`/`false`: строка `"false"`
в Python истинна, и принять её значило бы сделать обратное просьбе.

### Ответ

| Поле | Тип | Когда | Описание |
|---|---|---|---|
| `status` | `"ok"` или `"error"` | всегда | Результат |
| `id` | строка или число | если был в запросе | Копия `id` |
| `result` | зависит от команды | при `ok` | Полезная нагрузка |
| `code` | строка | при `error` | Машиночитаемый код ошибки |
| `message` | строка | при `error` | Пояснение для человека |
| `position` | число | при ошибке разбора JSON запроса | Индекс символа |

Клиент сначала смотрит на `status`. Решения принимаются по `code`, а `message`
только показывается: формулировки могут меняться, коды — нет.

### Пути

Все пути — **от каталога пользователя на сервере**, разделитель `/` (обратный
слеш тоже принимается). Пустая строка и `.` — корень каталога пользователя.
Абсолютные пути, буквы дисков, `..` и опасные для Windows имена отвергаются
кодом `BAD_PATH` (полный список — [security.md](security.md#4-обход-каталогов-path-traversal)).
В ответах пути тоже относительные, без ведущего `/`.

## 4. Команды

Без входа доступны только команды, отмеченные «открыта». Остальные до входа
отвечают `AUTH_REQUIRED`.

### 4.1 Служебные

| Команда | Доступ | Аргументы | Результат |
|---|---|---|---|
| `ping` | открыта | — | `"pong"` |
| `quit` | открыта | — | `"bye"`, после ответа сервер закрывает соединение |

### 4.2 Учётные записи

| Команда | Доступ | Аргументы | Результат |
|---|---|---|---|
| `register` | открыта | `username`, `password` | `{"username"}`, вход выполнен сразу |
| `login` | открыта | `username`, `password` | `{"username"}` — имя в том регистре, в каком хранится |
| `logout` | | — | `"ok"` |
| `whoami` | | — | `{"username"}` |

После пяти неудачных `login` в одном соединении сервер отвечает и закрывает
соединение. После пяти неудачных попыток подряд к одному логину учётная запись
блокируется на 5 минут (`ACCOUNT_LOCKED`).

### 4.3 Диски

`drives` — список дисков сервера:

```json
{"name": "C:\\", "type": "fixed", "filesystem": "NTFS", "label": "",
 "ready": true, "total_size": 510836776960, "total_free": 241145176064,
 "available_free": 241145176064}
```

| Поле | Смысл | Аналог в .NET `DriveInfo` |
|---|---|---|
| `name` | Корень диска или точка монтирования | `Name` |
| `type` | `fixed`, `removable`, `network`, `cdrom`, `ram`, `unknown` | `DriveType` |
| `filesystem` | NTFS, ext4, … | `DriveFormat` |
| `label` | Метка тома | `VolumeLabel` |
| `ready` | Готов ли (вставлен ли носитель) | `IsReady` |
| `total_size` | Объём, байт | `TotalSize` |
| `total_free` | Свободно всего | `TotalFreeSpace` |
| `available_free` | Свободно для пользователя, под которым работает сервер | `AvailableFreeSpace` |

Для неготового диска размеры и файловая система — `null`.

### 4.4 Файлы и каталоги

| Команда | Аргументы | Результат |
|---|---|---|
| `ls` | `path` (необяз., по умолчанию корень) | `{"path", "entries": [{"name", "type", "size", "modified"}], "truncated"}` |
| `info` | `path` | `{"path", "name", "type", "size", "created", "modified", "record"}` |
| `read` | `path` | `{"path", "content"}` |
| `write` | `path`, `content`, `overwrite` (необяз., `false`) | `{"path", "size", "created"}` |
| `delete` | `path` | `{"path"}` |
| `mkdir` | `path` | `{"path"}` |
| `rmdir` | `path` | `{"path"}` |

- `type` — `file`, `dir`, `link` или `other`. Ссылки не раскрываются.
- `ls` отдаёт не больше 1000 записей; если их больше, `truncated: true`.
- Время — UTC в виде `ГГГГ-ММ-ДД ЧЧ:ММ:СС`.
- `info` для файла добавляет `record` — запись о файле из базы (`id`,
  `created_at`, `modified_at`, `size`) или `null`, если файл появился в обход сервера.
- `read` и `write` работают с текстом в UTF-8 до 256 КБ. Метка BOM в начале
  файла снимается при чтении.
- `write` без `overwrite` на существующий файл отвечает `ALREADY_EXISTS`.
  `created` в ответе — `true`, если файл создан, `false`, если перезаписан.
- Родительский каталог должен существовать — каталоги не создаются молча.
- `delete` удаляет только файлы, `rmdir` — только пустые каталоги.

### 4.5 JSON и XML

| Команда | Аргументы | Результат |
|---|---|---|
| `json_read` | `path` | `{"path", "data"}` — `data` любой JSON-тип |
| `json_write` | `path`, `data`, `overwrite` | как у `write` |
| `xml_read` | `path` | `{"path", "tree"}` |
| `xml_write` | `path`, `content` **или** `tree`, `overwrite` | как у `write` |

Дерево XML представлено вложенными объектами:

```json
{"tag": "phone", "attrs": {"name": "iPhone 6"}, "text": "",
 "children": [{"tag": "price", "attrs": {}, "text": "40000", "children": []}]}
```

`xml_write` принимает либо текст документа (`content`) — он проверяется тем же
безопасным разбором, что и при чтении, и записывается как прислан, — либо
дерево (`tree`), из которого документ собирается с экранированием.

Отвергаются кодом `BAD_FORMAT`: JSON с повторяющимися ключами, `NaN`,
`Infinity`, вложенностью больше 32; XML с `<!DOCTYPE>` и объявлениями
сущностей, вложенностью больше 32 или больше 10 000 элементов.

### 4.6 ZIP

| Команда | Аргументы | Результат |
|---|---|---|
| `zip` | `archive`, `sources` (список путей), `overwrite` | `{"path", "size", "created", "files"}` |
| `zip_list` | `archive` | `{"archive", "entries": [{"name", "size", "compressed", "is_dir"}]}` |
| `unzip` | `archive`, `destination` (необяз.) | `{"destination", "files": [{"path", "size"}]}` |

- Имя архива должно оканчиваться на `.zip`. Каталоги в `sources` упаковываются
  рекурсивно, имена в архиве — пути от корня пользователя.
- `unzip` распаковывает только в **новый** каталог. Без `destination` — в
  каталог с именем архива без `.zip` рядом с ним.
- Отказ `UNSAFE_ARCHIVE`: имя записи выходит за каталог, абсолютное, с буквой
  диска; запись — символическая ссылка или зашифрована; повторяющиеся имена;
  больше 1000 записей, больше 100 МБ в распакованном виде, сжатие сильнее чем
  в 100 раз, фактический размер больше объявленного.

### 4.7 Журналы

| Команда | Аргументы | Результат |
|---|---|---|
| `log` | `limit` (1–500, по умолчанию 20) | Последние действия пользователя: `[{"id", "timestamp", "peer", "action", "target", "success", "details"}]` |
| `ops` | `limit`, `path` (необяз.) | Последние операции с файлами: `[{"id", "timestamp", "operation_type", "file_id", "filename", "location"}]` |

Новые записи первыми. Пользователь видит только свои записи. В `log`
`details` — код ошибки для неуспешных действий.

## 5. Коды ошибок

| Код | Когда | Соединение |
|---|---|---|
| `BAD_JSON` | Кадр не UTF-8, не JSON, не объект или слишком глубоко вложен | живо |
| `BAD_REQUEST` | Нет обязательного поля, неверный тип, значение вне диапазона | живо |
| `UNKNOWN_COMMAND` | Нет такой команды; в сообщении — список доступных | живо |
| `FRAME_TOO_LONG` | Кадр больше предела | **закрывается** |
| `SERVER_BUSY` | Достигнут предел одновременных клиентов | **закрывается** |
| `INTERNAL_ERROR` | Ошибка в сервере; подробности только в логе сервера | живо |
| `AUTH_REQUIRED` | Команда требует входа | живо |
| `AUTH_FAILED` | Неверный логин или пароль — что именно, не сообщается | живо, после 5-й неудачи **закрывается** |
| `ACCOUNT_LOCKED` | Учётная запись временно заблокирована | как у `AUTH_FAILED` |
| `ALREADY_LOGGED_IN` | `login` или `register` при выполненном входе | живо |
| `REGISTRATION_CLOSED` | Сервер запущен с `--no-registration` | живо |
| `BAD_USERNAME` | Логин не по правилам | живо |
| `WEAK_PASSWORD` | Пароль не по правилам | живо |
| `USER_EXISTS` | Логин занят (без учёта регистра) | живо |
| `BAD_PATH` | Путь отвергнут песочницей | живо |
| `NOT_FOUND` | Нет файла, каталога или родительского каталога | живо |
| `ALREADY_EXISTS` | Файл, каталог или архив уже есть | живо |
| `NOT_A_FILE` | Ожидался файл, а это каталог | живо |
| `NOT_A_DIRECTORY` | Ожидался каталог | живо |
| `DIR_NOT_EMPTY` | `rmdir` непустого каталога | живо |
| `FILE_TOO_LARGE` | Файл больше 256 КБ | живо |
| `NOT_TEXT` | Файл не в UTF-8 | живо |
| `ACCESS_DENIED` | Отказ ОС или файл занят другой операцией | живо |
| `BAD_FORMAT` | Некорректный или опасный JSON/XML | живо |
| `BAD_ARCHIVE` | Не ZIP или архив повреждён | живо |
| `UNSAFE_ARCHIVE` | Архив отвергнут проверками безопасности | живо |
| `LIMIT_EXCEEDED` | При упаковке превышен предел файлов или размера | живо |

## 6. Пример сессии

```
клиент → {"cmd":"ls"}
сервер ← {"status":"error","code":"AUTH_REQUIRED","message":"Команда доступна только после входа (login)"}

клиент → {"cmd":"register","username":"ivan","password":"secret123"}
сервер ← {"status":"ok","result":{"username":"ivan"}}

клиент → {"cmd":"write","path":"notes.txt","content":"Первая строка\nВторая\n"}
сервер ← {"status":"ok","result":{"path":"notes.txt","size":39,"created":true}}

клиент → {"cmd":"read","path":"../../etc/passwd"}
сервер ← {"status":"error","code":"BAD_PATH","message":"Переход в родительский каталог («..») недопустим"}

клиент → {"cmd":"zip","archive":"backup.zip","sources":["notes.txt"]}
сервер ← {"status":"ok","result":{"path":"backup.zip","size":158,"created":true,"files":1}}

клиент → {"cmd":"ops","limit":2}
сервер ← {"status":"ok","result":[{"id":2,"timestamp":"2026-10-09 10:21:41.520","operation_type":"create","file_id":2,"filename":"backup.zip","location":"backup.zip"},{"id":1,"timestamp":"2026-10-09 10:21:41.512","operation_type":"create","file_id":1,"filename":"notes.txt","location":"notes.txt"}]}

клиент → {"cmd":"quit"}
сервер ← {"status":"ok","result":"bye"}
                       (сервер закрывает соединение)
```

Каждая строка завершается переводом строки, который в примере не показан.
