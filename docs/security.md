# Безопасность

Документ описывает, от чего защищён файловый менеджер, как именно и чем это
проверено. Каждая угроза доведена до конкретного места в коде и до теста,
который её воспроизводит.

---

## 1. Модель угроз

### Что защищается

| Актив | Почему ценен |
|---|---|
| Файловая система сервера за пределами хранилища | Конфигурация, ключи, исходники, системные файлы |
| Файлы пользователя | Принадлежат только ему |
| Учётные данные | Пароли пользователей часто совпадают с паролями в других местах |
| Журналы операций и аудита | Единственный способ восстановить, кто что сделал |
| Доступность сервера | Сервер обслуживает всех, падение одного — отказ для всех |

### Кто атакует

| Нарушитель | Возможности |
|---|---|
| Сетевой клиент без учётной записи | Отправляет на порт произвольные байты |
| Вошедший пользователь | Отправляет произвольные пути, файлы, архивы, JSON и XML |
| Другой пользователь того же сервера | То же, плюс знает, что рядом лежат чужие файлы |
| Тот, кто получил копию базы | Видит таблицы целиком |

### Граница доверия

Всё, что пришло из сокета, — недоверенные данные: имя команды, путь,
содержимое файла, имя записи в ZIP-архиве, текст XML, значение в JSON.
Доверенными считаются только код сервера, файл схемы и конфигурация запуска.

## 3. SQL-инъекция

**Атака.** Логин `x' OR '1'='1` в запросе, собранном склейкой строк,
превращает условие `WHERE username = '...'` в истинное для любой строки.
Путь `a'); DROP TABLE users; --` удаляет таблицу.

**Защита.** Все запросы — подготовленные выражения: текст SQL и значения
передаются драйверу раздельно, значения подставляются через `?`. Значение
никогда не становится частью текста запроса, поэтому кавычки в нём — просто
символы.

```python
conn.execute("SELECT ... FROM users WHERE username = ?", (username,))
```

Правило легко нарушить случайно — одной f-строкой. Поэтому тест
`test_в_тексте_запросов_нет_данных` разбирает исходник `repository.py`
синтаксическим анализатором Python и проверяет, что первым аргументом каждого
`execute()` стоит только строковый литерал или константа `NOW`. Новый запрос
с f-строкой провалит тест раньше, чем попадёт в работу.

**Хранимые процедуры.** В SQLite их нет. Их роль — правило, которое живёт в
базе и выполняется при любом изменении данных, — выполняют триггеры:
журнал операций заполняется в базе, а не в коде сервера (см. [database.md](database.md)).

## 4. Обход каталогов (path traversal)

**Атака.** `read ../../etc/passwd`. Наивное `root / user_path` в Python
отдаёт файл за пределами хранилища, а абсолютный путь `C:\Windows\win.ini`
и вовсе заменяет корень целиком: `Path("storage") / "C:\\x"` равно `C:\x`.

**Защита в два слоя** (`server/fs/sandbox.py`):

1. **Синтаксический.** Путь разбирается на компоненты, разделителями считаются
   и `/`, и `\`. Отвергается:

   | Приём | Пример | Почему опасно |
   |---|---|---|
   | Родительский каталог | `../x`, `a/../../x` | Выход из песочницы |
   | Абсолютный путь | `/etc/passwd`, `\\server\share` | Замена корня |
   | Буква диска | `C:\x`, `C:x` | Замена корня на Windows |
   | Нулевой байт | `a.txt\x00.jpg` | Обрезает путь в системных вызовах |
   | Двоеточие | `a.txt:hidden` | Альтернативный поток NTFS — скрытые данные |
   | Имена устройств | `CON`, `nul.txt`, `COM1` | На Windows это устройства, а не файлы |
   | Точка или пробел в конце | `a.txt.` | Windows отбрасывает их: это тот же `a.txt` |
   | Управляющие символы, `<>"|?*` | | Недопустимы в именах Windows |

2. **Семантический.** Готовый путь разрешается `resolve()` — со всеми
   символическими ссылками, короткими именами 8.3 и регистром — и проверяется
   `is_relative_to(root)`. Это ловит ссылку внутри песочницы, указывающую наружу:
   синтаксически путь `escape/file` безупречен.

Проверка — по компонентам пути, а не `str(path).startswith(str(root))`:
каталог `user-10` начинается со строки `user-1`, и строковое сравнение пустило
бы одного пользователя к другому. Тест `test_соседний_каталог_с_тем_же_префиксом`.

**Изоляция пользователей.** Каталог пользователя называется по числовому id
из базы (`user-7`), а не по логину: имя каталога не зависит от данных клиента.

## 5. Небезопасная десериализация

**Атака.** Форматы, которые при чтении создают объекты произвольных классов
(`pickle` в Python, `BinaryFormatter` в .NET), исполняют код при разборе
подобранного файла. Достаточно, чтобы класс с опасным методом был доступен
программе.

**Защита.** `pickle` и подобные форматы не используются нигде. JSON
разбирается модулем `json`, который порождает только `dict`, `list`, `str`,
`int`, `float`, `bool`, `None` — класс объекта из файла выбрать нельзя.
Сверх этого (`server/fs/formats.py`):

| Что отвергается | Почему |
|---|---|
| Повторяющийся ключ `{"role":"user","role":"admin"}` | Разные разборщики берут разное значение: проверка видит одно, применение — другое |
| `NaN`, `Infinity` | Не входят в стандарт, ломают сравнения и чужие разборщики |
| Вложенность глубже 32 | Исчерпание стека |
| Вложенность на 100 000 уровней в самом запросе | `RecursionError` перехватывается и становится `BAD_JSON`, а не обрывом соединения |

## 6. XML: XXE и «миллиард смеющихся»

**Атаки.**

- XXE — внешняя сущность `<!ENTITY x SYSTEM "file:///etc/passwd">` подставляет
  в документ содержимое файла сервера, а `SYSTEM "http://..."` заставляет
  сервер сделать запрос во внутреннюю сеть.
- «Миллиард смеющихся» — десять вложенных сущностей, каждая из десяти
  предыдущих: килобайт текста разворачивается в гигабайты памяти.

Обе атаки работают через DTD — описание типа документа.

**Защита.** Документу с данными DTD не нужна, поэтому любой `<!DOCTYPE>` —
отказ. Разбор идёт напрямую через `expat` с обработчиками объявлений DTD и
сущностей, которые прерывают разбор на первом же объявлении — до того, как
что-либо будет развёрнуто или загружено. Дополнительно: не больше 10 000
элементов и 32 уровней вложенности.

Документ с DTD не только не читается, но и не записывается: `xml_write`
пропускает текст через тот же разбор. Иначе на диске оказался бы файл,
опасный для других программ, которые его откроют.

При сборке XML из дерева используется ElementTree, а не склейка строк:
текст `</note><admin/>` остаётся текстом. Тест `test_сборка_экранирует_данные`.

## 7. ZIP-архивы

| Атака | Пример | Защита |
|---|---|---|
| Zip Slip | запись `../../server/config.py` | Имя записи проходит правила пути из §4; итоговый путь сверяется с каталогом распаковки |
| Zip-бомба | 42 КБ → 4,5 ПБ | Не больше 1000 записей, 100 МБ суммарно, сжатие не больше чем в 100 раз |
| Ложный заголовок | В заголовке 10 байт, внутри мегабайт | Байты считаются при распаковке; превышение объявленного — отказ |
| Символическая ссылка | Запись-ссылка на `/etc`, затем `link/passwd` | Ссылки не распаковываются |
| Зашифрованная запись | | Содержимое нельзя проверить — отказ |
| Дубликаты | `a.txt` и `A.TXT` | На Windows это один файл — отказ |

Все проверки по заголовкам выполняются **до** записи первого байта. Распаковка
идёт во временный каталог, который после успеха переименовывается в целевой;
при отказе он удаляется целиком — половины архива на диске не остаётся.
Распаковка возможна только в новый каталог: иначе она молча перезаписала бы
существующие файлы.

## 8. Состояния гонки

Каждый клиент обслуживается своим потоком, поэтому два окна одного
пользователя работают параллельно.

| Гонка | Сценарий | Защита |
|---|---|---|
| TOCTOU при создании | Оба потока проверили «файла нет», оба записали, второй затёр первого | Проверка и запись под одной блокировкой пути (`fs/locks.py`) |
| Чтение недописанного файла | Читатель видит половину нового содержимого | Запись во временный файл и атомарная замена `os.replace` |
| Подмена между проверкой и открытием | Размер проверен по пути, а открыт уже другой файл | Размер проверяется `fstat` у открытого дескриптора |
| Потерянное приращение | Параллельные неудачные входы: «прочитать — прибавить — записать» теряет попытки | `failed_logins = failed_logins + 1` в одном SQL-запросе |
| Двойная регистрация | Два клиента регистрируют один логин | Арбитр — ограничение `UNIQUE` в базе, а не проверка в коде |
| Взаимная блокировка | Упаковка `a,b` и `b,a` одновременно | Замки захватываются в отсортированном порядке |
| Конкурентная запись в базу | «database is locked» | `BEGIN IMMEDIATE`: писатели выстраиваются в очередь |

На Windows файл нельзя заменить, пока его читает другой поток; замена
повторяется до 20 раз с паузой 25 мс, после чего клиент получает
`ACCESS_DENIED` вместо внутренней ошибки.

## 9. Аутентификация

**Хранение.** Пароль хешируется `scrypt` (n = 2¹⁴, r = 8, p = 1) с 16 байтами
случайной соли. Быстрые хеши (MD5, SHA-256) для паролей непригодны: видеокарта
перебирает миллиарды в секунду. `scrypt` намеренно медленный и требует памяти.
Параметры хранятся рядом с хешем, чтобы их можно было усилить позже. Ограничение
`CHECK (password_hash LIKE 'scrypt$%')` не даёт записать в базу пароль открытым
текстом даже по ошибке в коде.

**Сравнение.** `hmac.compare_digest` — за время, не зависящее от места
первого расхождения.

**Перебор.**

- после 5 неудачных попыток подряд учётная запись блокируется на 5 минут;
  во время блокировки пароль не проверяется вовсе;
- после 5 неудачных попыток в одном соединении сервер закрывает соединение —
  это мешает перебирать разные логины, не задевая блокировку каждого.

**Выяснение логинов.** На «нет такого логина» и «неверный пароль» один код
`AUTH_FAILED` и одно сообщение. Для несуществующего логина хеш всё равно
вычисляется — с фиктивным значением, — иначе ответ приходил бы заметно быстрее.

**Правила.** Логин — 3–32 символа `[A-Za-z0-9_.-]`, без учёта регистра
(`Admin` и `admin` — один пользователь). Пароль — 8–128 символов, не только
буквы и не только цифры, не равен логину.

## 10. Контроль доступа и аудит

**Запрет по умолчанию.** Проверка входа — в диспетчере, а не в обработчиках.
Команда закрыта, пока при регистрации её явно не пометили `public=True`.
Забытая проверка в одном из двадцати обработчиков означала бы дыру; здесь её
нельзя забыть. Открыты только `register`, `login`, `ping`, `quit`.

**Журнал аудита** (таблица `audit_log`). Запись делается в диспетчере для
каждой команды — успешной или нет, — включая попытки без входа и неудачные
входы с указанием логина, под которым пытались войти. Поля: время, пользователь,
адрес клиента, команда, объект (путь, архив или логин), успех, код ошибки.

Что в журнал **не** попадает: пароль и содержимое файлов. Объект берётся только
из явного списка полей (`path`, `archive`, `username`, `sources`,
`destination`), а не из всего запроса.

**Неизменяемость.** Триггеры запрещают `UPDATE` и `DELETE` для `audit_log` и
`operations`, удаление записей о файлах и подмену их владельца. Нарушитель,
получивший возможность выполнить запрос, первым делом попробует стереть следы;
теперь для этого ему придётся менять саму схему.

**Отладочный лог.** На уровне `DEBUG` сервер пишет сырые кадры — и пароль при
входе оказался бы в файле лога открытым текстом. Поле `password` маскируется
до записи (`***`), длинные кадры обрезаются до 300 байт.

## 11. Отказ в обслуживании

| Ресурс | Предел | По умолчанию |
|---|---|---|
| Кадр протокола | `FM_MAX_FRAME_SIZE` | 2 МБ |
| Файл, читаемый и записываемый целиком | `FM_MAX_FILE_SIZE` | 256 КБ |
| Одновременные клиенты | `FM_MAX_CONNECTIONS` | 64 |
| Простой клиента | `FM_IDLE_TIMEOUT` | 300 с |

| Вложенность JSON и XML | | 32 уровня |
| Элементы XML | | 10 000 |

Кадр обязан вмещать файл предельного размера в худшем случае экранирования
(байт `\x01` → шесть символов `\u0001`). Конфигурация, где это не так,
отвергается при запуске: иначе сервер разрешил бы записать файл, который
потом не сможет отдать.

## 12. Утечка информации

- Пути в ответах — относительно каталога пользователя. Абсолютный путь на
  сервере не попадает ни в ответы, ни в базу. Тест
  `test_ответы_не_раскрывают_путь_сервера`.
- Непредвиденная ошибка в обработчике возвращает клиенту `INTERNAL_ERROR` с
  нейтральным текстом; трассировка остаётся в логе сервера.
- Листинг показывает символическую ссылку как ссылку, не переходя по ней.

## 13. Что не защищено

Честный список ограничений текущей версии.

| Ограничение | Последствие | Как закрыть |
|---|---|---|
| Нет шифрования канала | Пароль и файлы идут по сети открытым текстом. Безопасно только на `localhost` или в доверенной сети | Обернуть сокет в TLS модулем `ssl` |
| Нет квоты на объём | Пользователь может заполнить диск множеством файлов по 256 КБ | Учитывать суммарный размер по реестру `files` |
| Подмена каталога ссылкой между `resolve()` и открытием | Требует доступа к файловой системе сервера в обход клиента | `openat` с `O_NOFOLLOW` (только POSIX) |
| Блокировка по логину раскрывает его существование | `ACCOUNT_LOCKED` приходит только для существующего логина | Отвечать `AUTH_FAILED` и при блокировке, теряя подсказку для честного пользователя |
| Список дисков показывает устройство сервера | Точки монтирования, метки томов | Требование задания; выдаётся только вошедшим |
| Файл базы не зашифрован | Тот, кто скопировал базу, видит журналы и хеши паролей | Шифрование диска средствами ОС; хеши паролей при этом остаются стойкими |
