# Руководство пользователя

Система состоит из двух программ: **сервера**, который вычисляет выражения, и
**клиента**, через который вводятся запросы. Обе запускаются в отдельных окнах
терминала.

---

## 1. Требования

| Требование | Значение |
|---|---|
| Python | 3.11 или новее |
| Операционная система | Windows, Linux, macOS |
| Дополнительные пакеты | не требуются |
| Свободный порт | 9000 (изменяем) |

Проверить установленный Python:

```bash
python --version
```

Если команда не найдена, в Windows попробуйте `py --version` — это системный
лаунчер, который присутствует всегда, даже когда `python` не прописан в `PATH`.
Во всех дальнейших примерах вместо `python` можно подставлять `py`.

---

## 2. Размещение

Проект должен находиться в одном каталоге целиком. Все команды выполняются
**из корневого каталога проекта** — того, в котором лежат папки `server`,
`client` и `common`.

Форма запуска `python -m server.main` означает «найти пакет `server` в текущем
каталоге». Из другого места он найден не будет.

---

## 3. Запуск сервера

Сервер запускается первым и остаётся работать всё время сеанса.

Команда зависит от того, какая оболочка используется. Определить её можно по
виду приглашения:

| Оболочка | Приглашение | Команда запуска |
|---|---|---|
| cmd.exe | `C:\путь>` | `cd /d "C:\MIREA\client-server" && python -m server.main` |
| PowerShell | `PS C:\путь>` | `cd "C:\MIREA\client-server"; python -m server.main` |
| Git Bash, Linux, macOS | `пользователь@машина$` | `cd "C:/MIREA/client-server" && python -m server.main` |

Различия существенны:

- в **cmd** команды разделяются `&&`, точка с запятой разделителем не является
  и попадёт в аргумент предыдущей команды;
- в **bash** разделителем пути служит только прямой слэш, обратный является
  экранирующим символом;
- **кавычки обязательны**, если в пути к проекту есть пробелы; для пути
  без пробелов они не мешают.

При успешном запуске выводится:

```
Сервер слушает 127.0.0.1:9000
Доступные команды: calc, history, ping, quit
Предел одновременных клиентов: 64
Остановка — Ctrl+C
```

Остановка — `Ctrl+C`.

---

## 4. Запуск клиента

Во **втором** окне терминала, не закрывая первое:

```bash
python -m client.main
```

При успешном подключении:

```
Подключено. `ping` — проверка связи, `quit` — выход.

>
```

Клиентов можно запустить несколько — сервер обслуживает их одновременно.

Выход — команда `quit` или `Ctrl+C`.

---

## 5. Команды клиента

| Ввод | Действие |
|---|---|
| выражение, например `2 + 2` | вычислить |
| `ping` | проверить связь с сервером |
| `history` | показать последние 10 вычислений |
| `history 5` | показать последние 5 вычислений |
| `quit` | завершить работу |
| строка, начинающаяся с `{` | отправить запрос протокола без изменений |

Последняя форма предназначена для отладки: она позволяет проверить поведение
протокола вручную. Например, `{"cmd":"history","limit":999}` вернёт ошибку
`BAD_REQUEST`, поскольку допустимый диапазон — от 1 до 50.

История ведётся **в пределах текущего соединения**: при переподключении она
очищается, а у разных клиентов не пересекается. Неудачные вычисления в историю
не попадают.

## 6. Синтаксис выражений

| Возможность | Примеры |
|---|---|
| Сложение и вычитание | `2 + 2`, `10 - 3` |
| Умножение и деление | `6 * 7`, `8 / 2` |
| Скобки любой вложенности | `(2 + 3) * 4`, `((1+2)*(3+4))/7` |
| Унарные знаки | `-5`, `+5`, `-(2+3)`, `--5` |
| Дробные числа | `0.5 + 0.25`, `10 / 4` |
| Пробелы в любом количестве | `2+2` и `  2  +  2  ` равнозначны |

Правила записи чисел:

- дробная часть отделяется **точкой**, запятая недопустима;
- точка обязана иметь цифры с обеих сторон: `5.` и `.5` ошибочны;
- запись числа не длиннее 100 символов.

Тип результата зависит от значения: `4 / 2` даёт `2`, а `5 / 2` даёт `2.5`.

Не поддерживаются: возведение в степень, остаток от деления, функции,
константы, переменные.

### Пример сеанса

```
> 2 + 3 * 4
14
> (2 + 3) * 4
20
> 10 / 4
2.5
> -(2 + 3)
-5
> 10 / 0
Ошибка [DIV_BY_ZERO]: Деление на ноль
  10 / 0
     ^
> history
  2 + 3 * 4 = 14
  (2 + 3) * 4 = 20
  10 / 4 = 2.5
  -(2 + 3) = -5
> quit
bye
Отключено.
```

Стрелка под выражением указывает место ошибки — сервер сообщает не только
что не так, но и где.

---

## 7. Сообщения об ошибках

### Ошибки в выражении

| Код | Что произошло | Что делать |
|---|---|---|
| `DIV_BY_ZERO` | Деление на ноль | Проверить делитель; он мог получиться нулём при вычислении |
| `SYNTAX_ERROR` | Выражение не соответствует правилам | Смотреть на указатель: пропущена скобка, оператор без операнда, два числа подряд |
| `UNKNOWN_CHAR` | Символ неизвестен | Допустимы только цифры, точка, четыре знака операций и скобки |
| `EXPR_TOO_LONG` | Выражение длиннее 1000 символов | Разбить на части |
| `DEPTH_EXCEEDED` | Скобки вложены глубже 50 уровней | Упростить выражение |
| `NUMBER_TOO_LARGE` | Число или результат вне допустимого диапазона | Уменьшить значения |

Различие между `UNKNOWN_CHAR` и `SYNTAX_ERROR`: первое означает, что символ
вообще не входит в язык (`2 $ 3`), второе — что символ допустим, но стоит не
на месте (`2 ** 3`).

### Ошибки протокола

Возникают при ручной отправке запросов или при неполадках связи.

| Код | Что произошло |
|---|---|
| `BAD_JSON` | Сообщение не разбирается как объект JSON |
| `BAD_REQUEST` | Отсутствует обязательное поле или значение недопустимо |
| `UNKNOWN_COMMAND` | Команда неизвестна; в тексте ошибки перечислены доступные |
| `FRAME_TOO_LONG` | Сообщение длиннее 4096 байт, соединение закрывается |
| `SERVER_BUSY` | Достигнут предел одновременных клиентов, попробуйте позже |
| `INTERNAL_ERROR` | Сбой на сервере; подробности в журнале сервера |

Ошибка в выражении **не разрывает соединение** — после неё можно продолжать
работу. Соединение закрывается только при `FRAME_TOO_LONG` и `SERVER_BUSY`.

## 8. Настройка

Параметры задаются аргументами командной строки либо переменными окружения.
Аргументы имеют приоритет.

| Аргумент | Переменная окружения | По умолчанию | Назначение |
|---|---|---|---|
| `--host` | `CALC_HOST` | `127.0.0.1` | Адрес прослушивания |
| `--port` | `CALC_PORT` | `9000` | Порт |
| `--log-level` | `CALC_LOG_LEVEL` | `INFO` | Подробность журнала |
| `--log-file` | — | не пишется | Дублировать журнал в файл |
| — | `CALC_IDLE_TIMEOUT` | `300` | Секунд до отключения молчащего клиента |
| — | `CALC_MAX_CONNECTIONS` | `64` | Предел одновременных клиентов |
| — | `CALC_MAX_FRAME_SIZE` | `4096` | Предельный размер сообщения, байт |
| — | `CALC_BACKLOG` | `16` | Длина очереди подключений |

Примеры:

```bash
python -m server.main --port 9100 --log-level DEBUG
```

```bash
python -m server.main --log-file logs/server.log
```

Уровень `DEBUG` показывает каждое прочитанное сообщение и каждый ответ — при
разборе неполадок это основной инструмент.

### Работа по локальной сети

На сервере:

```bash
python -m server.main --host 0.0.0.0
```

На другой машине (подставить адрес сервера):

```bash
python -m client.main --host 192.168.1.10
```

Обмен идёт **без шифрования**, поэтому выставлять сервер в интернет не следует.
Может потребоваться разрешение в брандмауэре.

## 9. Устранение неполадок

**«Системе не удается найти указанный путь»**

Команда набрана в cmd, где разделителем служит `&&`, а не точка с запятой.
Точка с запятой попадает в аргумент `cd`. Используйте форму для cmd из
раздела 3.

**«Сервер 127.0.0.1:9000 недоступен. Запущен ли он?»**

Сервер не запущен, запущен на другом порту либо остановлен. Проверьте первое
окно терминала.

**«Address already in use» / «Адрес уже используется»**

Порт занят — вероятно, предыдущим экземпляром сервера. Закройте его или
запустите на другом порту: `python -m server.main --port 9100`. Клиент
запускайте с тем же портом.

**Русский текст выводится нечитаемыми символами**

Кодовая страница консоли отличается от UTF-8. В cmd выполните `chcp 65001`
перед запуском либо задайте переменную окружения `PYTHONIOENCODING=utf-8`.

**`python` не является внутренней или внешней командой**

Python не прописан в `PATH`. В Windows используйте `py` вместо `python`.

**`No module named server`**

Команда запущена не из корневого каталога проекта. Перейдите в каталог, где
находятся папки `server` и `client`.

**Клиент получил `SERVER_BUSY`**

Достигнут предел одновременных подключений. Закройте лишние клиенты либо
запустите сервер с бо́льшим пределом:
`CALC_MAX_CONNECTIONS=128 python -m server.main` (в cmd:
`set CALC_MAX_CONNECTIONS=128` отдельной командой).

## 10. Проверка работоспособности

Полный набор автоматических проверок запускается одной командой, сервер при
этом поднимать не нужно — тесты делают это сами:

```bash
python -m unittest discover
```

Ожидаемый результат — `OK` и 129 пройденных тестов. Подробности в
[testing.md](testing.md).
