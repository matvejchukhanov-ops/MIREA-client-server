# Руководство пользователя

Система состоит из двух программ: **сервера**, который хранит файлы
пользователей и ведёт базу данных, и **клиента**, через который вводятся
команды. Обе запускаются в отдельных окнах терминала.

---

## 1. Требования

| Требование | Значение |
|---|---|
| Python | 3.11 или новее |
| Операционная система | Windows, Linux (в том числе Astra Linux), macOS |
| Дополнительные пакеты | не требуются: SQLite, zipfile, json, xml входят в Python |
| Свободный порт | 9000 (изменяем) |

Проверить установленный Python:

```bash
python --version
```

Если команда не найдена, в Windows попробуйте `py --version`. В Linux
команда может называться `python3`. Во всех примерах ниже `python` можно
заменить на `py` или `python3`.

---

## 2. Размещение

Все команды выполняются **из корневого каталога проекта** — того, в котором
лежат папки `server`, `client` и `common`. Форма `python -m server.main`
ищет пакет `server` в текущем каталоге.

При первом запуске сервер сам создаст рядом:

| Каталог | Что в нём |
|---|---|
| `storage/` | Файлы пользователей, по каталогу на каждого |
| `data/filemanager.db` | База данных SQLite |

Оба каталога исключены из репозитория.

---

## 3. Запуск сервера

| Оболочка | Команда |
|---|---|
| cmd.exe | `cd /d "C:\MIREA\client-server" && python -m server.main` |
| PowerShell | `cd "C:\MIREA\client-server"; python -m server.main` |
| Git Bash, Linux | `cd ~/client-server && python -m server.main` |

При успешном запуске:

```
Сервер слушает 127.0.0.1:9000
Хранилище: C:\MIREA\client-server\storage
База данных: C:\MIREA\client-server\data\filemanager.db
Доступные команды: delete, drives, info, json_read, json_write, log, login, ...
Предел одновременных клиентов: 64
Остановка — Ctrl+C
```

---

## 4. Запуск клиента

Во **втором** окне терминала, не закрывая первое:

```bash
python -m client.main
```

Клиентов можно запустить несколько — сервер обслуживает их одновременно,
в том числе несколько окон одного пользователя.

Выход — `quit` или `Ctrl+C`.

---

## 5. Команды клиента

Список команд выводит `help`.

| Команда | Действие |
|---|---|
| `register <логин>` | Регистрация. Пароль спрашивается дважды и не отображается. После регистрации вход выполнен |
| `login <логин>` | Вход |
| `logout`, `whoami` | Выход из учётной записи, кто вошёл |
| `drives` | Диски сервера: тип, файловая система, объём, свободное место |
| `ls [путь]` | Содержимое каталога |
| `info <путь>` | Свойства файла и его запись в базе |
| `cat <путь>` | Прочитать текстовый файл |
| `write <путь> [--force]` | Записать текстовый файл |
| `rm <путь>` | Удалить файл |
| `mkdir <путь>`, `rmdir <путь>` | Создать каталог, удалить пустой каталог |
| `json-read <путь>`, `json-write <путь> [--force]` | Прочитать и записать JSON |
| `xml-read <путь>`, `xml-write <путь> [--force]` | Прочитать и записать XML |
| `zip <архив.zip> <путь> [путь ...] [--force]` | Упаковать файлы и каталоги |
| `zip-list <архив.zip>` | Содержимое архива |
| `unzip <архив.zip> [каталог]` | Распаковать в новый каталог |
| `log [N]` | Журнал ваших действий (по умолчанию 20 последних) |
| `ops [N] [путь]` | Журнал операций с файлами: создание, изменение, удаление |
| `ping`, `quit` | Проверка связи, выход |

**Пути** — от вашего каталога на сервере, через `/`. Корень — пустой путь или
`.`. Подняться выше своего каталога нельзя. Путь с пробелами берётся в кавычки:
`cat "мои документы/план.txt"`.

**Многострочный ввод** (`write`, `json-write`, `xml-write`) завершается строкой
из одной точки.

**Перезапись.** Если файл уже есть, клиент спросит, перезаписать ли его.
Флаг `--force` перезаписывает без вопроса.

**Отладка протокола.** Строка, начинающаяся с `{`, уходит на сервер без
изменений: `{"cmd":"read","path":"../x"}`.

## 6. Сообщения об ошибках

Ошибка выводится как `Ошибка [КОД]: пояснение` и **не разрывает соединение**,
кроме случаев, указанных ниже. Самые частые:

| Код | Что значит | Что делать |
|---|---|---|
| `AUTH_REQUIRED` | Команда доступна только после входа | `login` или `register` |
| `AUTH_FAILED` | Неверный логин или пароль | Проверить раскладку и Caps Lock |
| `ACCOUNT_LOCKED` | Пять неудачных входов подряд | Подождать 5 минут |
| `WEAK_PASSWORD` | Пароль короче 8 символов, только буквы или только цифры, совпадает с логином | Выбрать другой |
| `BAD_PATH` | Путь выходит за ваш каталог или содержит недопустимые символы | Путь от своего каталога, без `..`, `:`, `*`, `?` |
| `NOT_FOUND` | Нет файла или родительского каталога | `ls`, при необходимости `mkdir` |
| `ALREADY_EXISTS` | Файл уже есть | `--force` или ответить `y` на вопрос клиента |
| `FILE_TOO_LARGE` | Файл больше 256 КБ | — |
| `NOT_TEXT` | Файл не в UTF-8 (например, картинка) | Читать нельзя, но можно упаковать в ZIP |
| `BAD_FORMAT` | Некорректный JSON/XML, повторяющиеся ключи, `<!DOCTYPE>` в XML | Исправить документ |
| `UNSAFE_ARCHIVE` | Архив отвергнут проверками: пути наружу, ссылки, zip-бомба | Не распаковывать такой архив |

После пяти неудачных `login` подряд сервер закрывает соединение — клиент
нужно запустить заново. Полный список кодов — [protocol.md](protocol.md#5-коды-ошибок).

## 7. Настройка сервера

Аргументы командной строки имеют приоритет над переменными окружения.

| Аргумент | Переменная | По умолчанию | Назначение |
|---|---|---|---|
| `--host` | `FM_HOST` | `127.0.0.1` | Адрес прослушивания |
| `--port` | `FM_PORT` | `9000` | Порт |
| `--storage` | `FM_STORAGE` | `storage` | Каталог файлов пользователей |
| `--db` | `FM_DB` | `data/filemanager.db` | Файл базы данных |
| `--no-registration` | `FM_ALLOW_REGISTRATION=0` | регистрация открыта | Запретить регистрацию |
| `--log-level` | `FM_LOG_LEVEL` | `INFO` | Подробность лога |
| `--log-file` | — | не пишется | Дублировать лог в файл |
| — | `FM_MAX_FILE_SIZE` | `262144` | Предел файла для `cat`/`write`, байт |
| — | `FM_MAX_FRAME_SIZE` | `2097152` | Предел сообщения, байт; должен вмещать файл с учётом экранирования |
| — | `FM_MAX_CONNECTIONS` | `64` | Одновременных клиентов |
| — | `FM_IDLE_TIMEOUT` | `300` | Секунд до отключения молчащего клиента |
| — | `FM_ZIP_MAX_ENTRIES` | `1000` | Записей в распаковываемом архиве |
| — | `FM_ZIP_MAX_TOTAL_SIZE` | `104857600` | Распакованный размер, байт |
| — | `FM_ZIP_MAX_RATIO` | `100` | Наибольшая степень сжатия записи |
| — | `FM_MAX_LOGIN_FAILURES` | `5` | Неудачных входов до блокировки |
| — | `FM_LOCKOUT_SECONDS` | `300` | Длительность блокировки |

Пример: отдельное хранилище и подробный лог в файл.

```bash
python -m server.main --storage D:/fm/storage --db D:/fm/fm.db --log-level DEBUG --log-file logs/server.log
```

На уровне `DEBUG` в лог пишутся сообщения клиентов (до 300 байт); пароль
при этом заменяется на `***`.

### Работа по локальной сети

На сервере `python -m server.main --host 0.0.0.0`, на другой машине
`python -m client.main --host 192.168.1.10`. Обмен идёт **без шифрования**:
пароль передаётся открытым текстом. В интернет такой сервер выставлять нельзя.

## 8. Устранение неполадок

**«Сервер 127.0.0.1:9000 недоступен. Запущен ли он?»** — сервер не запущен или
запущен на другом порту.

**«Address already in use»** — порт занят предыдущим экземпляром. Закройте его
или выберите другой порт: `--port 9100` у сервера и у клиента.

**«Не удалось подготовить хранилище или базу данных»** — нет прав на запись
в каталог запуска. Укажите `--storage` и `--db` в доступном месте.

**Русский текст нечитаем** — в cmd выполните `chcp 65001` перед запуском.

**`No module named server`** — команда запущена не из корня проекта.

**Клиент получил `SERVER_BUSY`** — достигнут предел подключений; закройте лишние
клиенты или увеличьте `FM_MAX_CONNECTIONS`.

**Как посмотреть базу напрямую** — см. [database.md](database.md#6-где-лежит-и-как-посмотреть).

## 9. Проверка работоспособности

Автоматические тесты поднимают сервер сами, во временном каталоге:

```bash
python -m unittest discover
```

Ожидаемый результат — `OK`. Подробности — [testing.md](testing.md).
