# Безопасный файловый менеджер — система клиент-сервер

Учебный проект по дисциплине «Разработка безопасного программного обеспечения»,
семестровое задание № 1. Сервер хранит файлы пользователей, работает с
текстом, JSON, XML и ZIP, показывает диски и ведёт базу данных SQLite с
пользователями, реестром файлов и журналами. Клиент — консольное приложение.

Главное в работе — не сами операции, а то, что они **не дают пользователю
больше, чем разрешено**: ни путём `../../etc/passwd`, ни архивом с записью
`../server/config.py`, ни XML с внешней сущностью, ни логином `x' OR '1'='1`.
Каждая такая атака воспроизведена тестом.

## Возможности

| Требование задания | Команды клиента |
|---|---|
| Диски и свойства файловой системы | `drives` |
| Чтение, запись, удаление файлов | `ls`, `info`, `cat`, `write`, `rm`, `mkdir`, `rmdir` |
| JSON и XML | `json-read`, `json-write`, `xml-read`, `xml-write` |
| ZIP-архивы | `zip`, `zip-list`, `unzip` |
| Файлы и операции в базе данных | `ops` |
| Журнал действий пользователей | `log` |
| Вход | `register`, `login`, `logout`, `whoami` |

## Защита

| Угроза | Как закрыта |
|---|---|
| SQL-инъекция | Только подготовленные выражения; тест разбирает исходник и ловит f-строки в SQL |
| Обход каталогов | Путь разбирается на компоненты и сверяется с корнем после `resolve()` |
| Небезопасная десериализация | Никакого `pickle`; JSON без дубликатов ключей, NaN и глубокой вложенности |
| XXE, «миллиард смеющихся» | Любой `<!DOCTYPE>` — отказ до разворачивания сущностей |
| Zip Slip, zip-бомбы | Проверка имён записей, пределы размера и сжатия, счёт байт при распаковке |
| Состояния гонки | Блокировки путей, атомарная замена файлов, приращения внутри SQL |
| Подбор пароля | scrypt с солью, блокировка учётной записи, разрыв соединения |
| Сокрытие следов | Журналы только дополняются — запрещено триггерами в базе |

Подробно — [docs/security.md](docs/security.md).

## Стек

| Компонент | Что используется |
|---|---|
| Язык | Python 3.11+ |
| Транспорт | `socket`, поток на клиента (`threading`) |
| Протокол | JSON по строке на сообщение |
| База данных | SQLite (`sqlite3`) |
| Пароли | `hashlib.scrypt` |
| XML | `xml.parsers.expat`, `xml.etree.ElementTree` |
| Архивы | `zipfile` |
| Тесты | `unittest` |

**Внешних зависимостей нет** — ни у кода, ни у тестов.

## Структура

```
client-server/
├── common/framing.py        границы сообщений поверх TCP
├── server/
│   ├── main.py              точка входа
│   ├── config.py            настройки и пределы
│   ├── tcp_server.py        accept, поток на клиента
│   ├── connection.py        обмен с одним клиентом
│   ├── protocol.py          разбор запросов, коды ошибок
│   ├── dispatcher.py        контроль доступа и журнал аудита
│   ├── handlers.py          команды
│   ├── app.py               сборка зависимостей
│   ├── session.py           состояние соединения
│   ├── auth/                scrypt, регистрация, вход
│   ├── db/                  схема SQLite, запросы
│   └── fs/                  песочница, файлы, JSON/XML, ZIP, диски
├── client/                  консольный клиент
├── tests/                   233 теста
└── docs/                    документация
```

## Запуск

Нужен только Python 3.11+. Устанавливать ничего не требуется.

Сервер (первым, в отдельном окне):

```bash
python -m server.main
```

Клиент (во втором окне):

```bash
python -m client.main
```

Сервер создаст `storage/` для файлов и `data/filemanager.db` для базы.
Дальше в клиенте:

```
> register ivan
Пароль:
Повторите пароль:
Вы вошли как ivan
ivan> write hello.txt
Введите текст файла. Конец ввода — строка «.»:
Привет!
.
Создан /hello.txt (14 Б)
ivan> cat ../../etc/passwd
Ошибка [BAD_PATH]: Переход в родительский каталог («..») недопустим
ivan> log 2
  2026-10-09 10:22:00  ok  write hello.txt
  2026-10-09 10:22:00  ОШ  read ../../etc/passwd  [BAD_PATH]
```

Все команды — `help` в клиенте. Параметры сервера (`--port`, `--storage`,
`--db`, `--no-registration`, переменные `FM_*`) — в
[руководстве пользователя](docs/user-guide.md#7-настройка-сервера).

## Тесты

```bash
python -m unittest discover
```

Сервер запускать не нужно: тесты поднимают его сами во временном каталоге.
